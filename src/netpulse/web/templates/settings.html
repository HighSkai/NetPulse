How checks work

  • The check loop runs every {{ interval_s }} s and checks every device that is due, up to 32 at once. Each device has its own interval, {{ interval_s }} s unless you change it on the device's edit page.
  • A device is checked by ping, or by connecting to a TCP port you choose, for devices that ignore ping.
  • An outage starts after {{ down_after }} failed checks in a row, and that is what alerts go by.
  • Degraded looks at the last {{ window }} checks.

Help

NETPULSE(1)NetPulse manual

NAME

netpulse — a network monitor for your own network

SYNOPSIS

netpulse [--db PATH] [--port N] [--local-only] [--open] [--debug]
netpulse [--db PATH] reset-password NAME
netpulse [--db PATH] users

DESCRIPTION

NetPulse checks every device on its interval, keeps the results in a SQLite file, and serves these pages to whoever signs in: on this PC only, until an administrator turns on access from the network. Nothing is sent anywhere else, except the notifications and checks from outside an administrator sets up.

ACCOUNTS

An administrator may do everything. A viewer may look at everything except packet captures and change nothing, unless an administrator grants single permissions. A lost password is reset by an administrator, or with netpulse reset-password NAME on the PC NetPulse runs on.

STATES

● Up
the last check got an answer
▲ Degraded
up, but its last {{ window }} checks were slow or kept failing, by the thresholds above
✕ Down
the last check got no answer; {{ down_after }} in a row start an outage
○ Not checked
no check yet
‖ Paused
not checked, and never alerted on, until someone resumes it

MOTION

The background drifts, the status dot pulses while checks run, a row flashes when it changes, and menus, dialogs and messages ease into place. Motion in the status bar switches all of it off in this browser. Nothing moves when the device is set to reduce motion.
